## 1. Layout & Shell

**The frame (must match 1.0's silhouette):**
- **Header** (full width): character name; class(es)+subclass+level; background; player name;
  race; alignment; XP value + progress to next level + Level-Up affordance; quick toggles
  for Rest, Equipment, theme, and a stats-drawer toggle on narrow screens; Back/exit.
  - **[NEW IN 2.0]** header must render **multiclass** as `Fighter 5 / Wizard 3` and show a
    combined character level + per-class levels.
- **Left column** — "who the character is" (identity + derived vitals): Vitals, Conditions,
  Summons, Abilities/Skills/Saves, Racial Actions, Features.
- **Center column** — "what the character does this turn": Turn economy header, Next-Turn
  checklist, Action list.
- **Right column** — "the detail surface": a single mutually-exclusive stack that shows the
  detail view for whatever is currently selected (action, spell, feature, skill, save, item,
  summon, death saves), plus the Level-Up / Spell-Selection / Equipment+Shop / Rest flows.

**Navigation model (the spine of the UX):** selecting any entity anywhere in the left/center
columns opens its **detail view** in the right column. Only one detail view is visible at a
time. This is the mechanism that satisfies "everything must have a detail visualization."

**Responsive rule:** ≥1000px shows all three columns; <1000px collapses the left column into a
drawer (hamburger in header). Center+right stack. Same breakpoint behavior as 1.0.

**Global overlays (float above the 3 columns):** Character-Select screen (entry point),
Dice-Roller overlay (d4–d100 + modifier + history), Rest dialog, Shop, Summon catalog/editor.

## 2. The Universal Detail-View Contract

Every entity's detail view (Section 5) is an instance of this one template. Define it once;
each entity just specifies what fills each slot. This is the most important pattern in 2.0.

A detail view has up to **six slots** (omit slots that don't apply to an entity):

1. **Identity header** — name, type/category badge, source (class/race/feat/spell/homebrew),
   icon/sprite, and key tags (level, school, rarity, action cost, recharge).
2. **Mechanical stat block** — the structured numbers/keywords: e.g. a spell's level/range/
   components/duration/save/attack/damage; a weapon's damage dice + properties; a condition's
   mechanical effects; a resource's used/total; a summon's HP/AC/speed/attacks.
3. **Computed values** — anything the rules engine derives for *this* character right now
   (e.g. this spell's save DC and attack bonus, this weapon's to-hit and damage *with* mods,
   max uses of a resource at this level). Shows the breakdown, not just the total.
4. **Rules text (5e)** — the RAW description/rule, in player-readable prose. Always present.
5. **Interactive controls** — the actions you can take from the detail view: cast / attack /
   toggle on-off / spend a use / equip / attune / apply condition / summon / edit (homebrew).
   Controls dispatch state changes; they never contain rules math.
6. **Cross-links** — links to related entities' detail views (a feat that grants a spell links
   to that spell; a subclass links to its features; a condition links to the spell that causes
   it). Powers "everything is connected."

**Builder rule:** in 2.0, implement this as ONE polymorphic detail-view component that takes
an entity descriptor and renders these slots — not 25 bespoke panels. (1.0 has ~8 separate
detail panels; consolidating them is an explicit 2.0 goal.)

## 3. Domain & Rules Engine (stack-agnostic, pure)

The engine is a set of **pure functions over the character state** — no UI, no storage, no
side effects. Any stack implements them identically. Grouped by concern, with 1.0 status.

**Core math**
- ability modifier `mod(score)`; proficiency bonus from level; point-buy cost table; 4d6-drop-lowest. ✅
- HP delta with temp-HP rules (damage depletes temp first, then real; heal → real only, capped). ✅

**Defense / movement**
- **Armor Class** — best-of formula set: unarmored (10+DEX), racial natural AC, subclass
  unarmored defense (Barbarian/Monk/etc.), armored (base+capped DEX+shield+enchant+Defense
  style), plus Mage-Armor-style overrides and Bladesong; then + equipment AC + condition AC
  delta. ✅
- **Speed** — race base + equipment + subclass buff, × condition speed-multiplier (floored). ✅
- **Initiative** — DEX + Alert + Jack-of-All-Trades / Remarkable Athlete + equipment DEX. ✅
- **Darkvision** — max(race, subclass). ✅
- **Condition modifiers** — fold active conditions into { acDelta, speedMultiplier, saveDeltas,
  flags } from a structured `mechanic` per effect. ✅
- **[NEW IN 2.0]** enforce **condition immunities/resistances** (a creature immune to a
  condition can't receive it; resistances halve relevant damage). 🆕

**Offense**
- weapon proficiency check (class/race/subclass; unarmed/natural always; custom→proficient). ✅
- **attack bonus** — ability mod (STR/DEX/finesse/Hex-Warrior CHA) + PB (if proficient) +
  weapon/enchant + Archery. ✅
- **weapon damage** — versatile handling, ability mod, enchant, equipment riders (same-type
  fold, other-type appended). ✅
- **crit threshold** — base 20; Champion 19/18; weapon/gear reductions; floor 10. ✅
- **special attacks / riders** — Sneak Attack, Reckless, Brutal/Divine Smite, GWM/Sharpshooter
  −5/+10, Hunter's Mark, Piercer/Crusher crit riders, Spell Sniper range. ✅/🟡

**Spellcasting**
- spellcasting ability (class or subclass override) → save DC (8+PB+mod) and attack (PB+mod). ✅
- Arcane-Archer DC (INT, non-caster). ✅
- **spell damage** — base dice, magic-missile/fire-bolt special cases, upcast scaling,
  equipment damage riders, hit/miss formulas. ✅
- prepared-spell count (Paladin level/2+mod; Cleric/Druid/Wizard/Artificer level+mod). ✅
- spells-known / cantrips-known progression and **level-up deltas** (spells+cantrips gained,
  max slot level), subclass-aware. ✅
- spell slots per class/level/subclass (incl. Warlock Pact Magic, half-casters, third-casters). ✅

**Progression**
- XP thresholds (level↔XP both ways). ✅
- available actions (generic + class + subclass + feat + weapon-derived + spell actions),
  Extra-Attack scaling, level-gated, resource-costed. ✅
- **[NEW IN 2.0] multiclassing — FULL PHB optional rule.** 🆕 The single largest new rules
  surface. Implement all of:
  - **Prerequisites:** to take a level in a class you must meet its ability minimum (e.g. STR 13
    for Fighter, CHA 13 for Sorcerer/Warlock/Paladin/Bard, both for some); enforce on level-up.
  - **Proficiency-on-entry:** entering a new class grants only the *reduced* multiclass prof set
    (not the full starting set) — specific armor/weapon/skill/save subsets per PHB table. Saves
    proficiencies do NOT get added for a second class.
  - **Combined caster level → multiclass spell-slot table:** sum full-caster levels + ½ half-caster
    (Paladin/Ranger, round down) + ⅓ third-caster (EK/AT) → a single shared slot table; Warlock
    **Pact Magic slots are tracked separately** and don't merge.
  - **Spells known/prepared per class independently** (each class uses its own ability + rules);
    a spell slot from the shared table can cast any prepared spell of sufficient level.
  - **Hit-Dice pooling** by die size; max HP sums each class's per-level contribution with the
    single shared CON mod.
  - **ASI/feat cadence is per-class** (each class's own ASI levels), and **proficiency bonus is by
    total character level** (not per class).
- **[NEW IN 2.0]** **legendary & lair actions** for summons/statblocks. 🆕

**Resources & rest**
- resource defaults per class/level (Ki, Rage, Sorcery Points, Bardic Inspiration, Channel
  Divinity, Action Surge, Second Wind, Lay on Hands pool, Superiority Dice, Infusions, …). ✅
- **short rest** — spend Hit Dice (roll + CON), recover short-rest resources, Warlock slots,
  racial-action recharges. ✅
- **long rest** — full HP, recover up to half level in HD, reset all resources/slots/prepared,
  drop concentration/summons/rage/Bladesong, clear conditions except exhaustion (exhaustion −1). ✅

> **Boundary contract (carry into 2.0):** rules math lives ONLY in this engine. State actions
> call it; UI/detail-views read its outputs and dispatch actions. No rules math in components
> or storage. Entities reference items/spells/feats/conditions **by string ID**, never embedded.

## 4. Data Model & Persistence

**The `Character` aggregate (one JSON document per character).** Field groups (full schema in
`entities/character/types.ts` is the canonical source; this is the map):
- **Identity:** id, schemaVersion, timestamps, name, playerName, alignment, race, classId,
  subclass(+locked), background, level, experiencePoints. **[NEW IN 2.0]** a `classes[]` for
  multiclass (each: classId, level, subclass) with `classId`/`level` kept as the primary class
  for back-compat.
- **Vitals:** abilityScores{str…cha}, hitPoints{current,max,temp}, deathSaves{successes,
  failures}, armorClass, speed, initiative, proficiencyBonus, bonusHpPerLevel.
- **Equipment/items:** equipment{armor,shield,helmet,necklace,cape,legs,boots,gloves,quiver,
  ring1,ring2,amulet}, weapons[] (idx0 main / idx1 off-hand; two-handed clears off-hand),
  ownedItemIds[], attunedItemIds[] (max 3), gold.
- **Proficiencies:** savingThrowProficiencies[], skillProficiencies{skill→proficient|expert}.
- **Spellcasting:** spellIds[], preparedSpellIds[], concentrationSpellId, spellSlots{lvl→
  {used,total}}, masterySpells, activeBuffSpells[].
- **Resources/state:** resources{name→{used,total}}, inspiration, hitDiceUsed, conditionIds[].
- **Class/subclass features:** feats[], featChoices{featId→ability}, completedAsiLevels[],
  completedAsiChoices, plus subclass-specific carriers — arcaneShots/activeArcaneShot,
  chosenManeuvers/selectedManeuver/activeManeuver/superiorityDiceUsed, warlockInvocations/
  pactBoon/pactBoonLocked/tomeCantrips/chainFamiliarType, hexWarriorWeaponId, isRaging,
  isBladesinging, chosenTotem, fightingStyle/Locked, circleOfLandTerrain, artificerInfusions/
  active, customFeatures[], and feat flags (piercerCritExtraDie, crusherCritAdvantage,
  spellSniperDoubleRange, mountedCombatantFlags).
- **Summons:** activeSummons[] (template/base/runtime split — see §5).
- **Notes:** notes.

**Other entity schemas (canonical files in parens):** Weapon, Equipment/Gear, AbilityScores,
HitPoints, SpellSlots, ActiveCondition (`entities/character/types.ts`); Condition + effect
mechanics (`entities/condition/types.ts`); Spell (`entities/spell/types.ts` /
`shared/data/spellData.ts` `SpellEntry`); Class/Subclass/Race defs (`shared/data/*`); Summon
template/base/runtime (`entities/summon/types.ts`).

**Persistence (stack-agnostic contract):**
- One document per character, addressed by id; a list/load/save/delete interface plus a
  file read/write for shared data (equipment CSV, summon JSON).
- 1.0 ships two adapters (desktop IPC + mobile filesystem) behind one interface. 2.0 keeps the
  **adapter boundary** so it runs offline-first on desktop AND mobile.
- **Schema migrations:** a linear, versioned upgrade chain run on load (1.0 is at **v11**).
  2.0 starts a fresh `schemaVersion` baseline but MUST ship an **importer** that reads a v11
  document and maps it forward (esp. into the new multiclass `classes[]`). Migration is
  forward-only with defaulting for missing fields. **[NEW IN 2.0]** v11→2.0 import.

## 5. Entity Catalog

Each entry: **purpose → schema → detail-view (per §2 contract) → 5e rules surfaced → data
source → count → status**. Content sets use schema+examples+count (not full enumeration).

### 5.1 Class  ✅
- **Purpose:** the character's primary archetype; drives hit die, proficiencies, spellcasting,
  resources, features, ASI levels.
- **Schema (`ClassDef`, `shared/data/classData.ts`):** id, name, hitDie(6/8/10/12), primaryAbility,
  savingThrows[2], armor/weaponProficiencies, skillOptions+count, spellcastingAbility?,
  isSpellcaster, spellsKnownTable, cantripsKnownTable, prepareSpells, asiLevels[], resources[].
- **Detail view:** identity(name, hit die, primary ability) · stat block(profs, save profs,
  caster type, ASI levels) · computed(this character's HP contribution, slot table at level) ·
  rules text(class description) · controls(none / pick at creation / level-up entry) ·
  cross-links(subclasses, class features, resources).
- **5e rules:** class table, proficiencies, spellcasting progression, ASI cadence.
- **Count:** 12 (Barbarian, Bard, Cleric, Druid, Fighter, Monk, Paladin, Ranger, Rogue,
  Sorcerer, Warlock, Wizard, Artificer). **[NEW IN 2.0]** a class is selectable multiple times
  via multiclassing.

### 5.2 Subclass  ✅
- **Purpose:** specialization chosen at the class's subclass level; adds features, sometimes
  spellcasting, unarmored AC, extra profs, special resources.
- **Schema (`SubclassDef`, `subclassData.ts`):** id, label, classId, unlocksAtLevel,
  extra(Armor/Weapon/Skill/Tool)Proficiencies, extraSkillChoice, unarmoredAC(formula),
  spellcastingAbility?, arcaneShotAbility?, spells/cantripsKnownTable, spellListClassId,
  subclassFeatures[](level,name,desc), subclassSpells{lvl→ids}, restrictedRaces?,
  darkvisionRange?, channelDivinityDesc?.
- **Detail view:** identity(label, parent class, unlock level) · stat block(granted profs,
  unarmored AC, bonus spells) · computed(features unlocked at current level) · rules text ·
  controls(pick during level-up) · cross-links(parent class, its features, granted spells).
- **5e rules:** subclass features by level, domain/oath/patron specifics, granted spell lists.
- **Count:** 112 across all 12 classes (canonical list = `subclassData.ts`).

### 5.3 Domain (Cleric)  ✅
- **Purpose:** Cleric's subclass; modeled AS a subclass (unlocksAtLevel 1) with domain spells +
  Channel Divinity options. Catalogued separately because the user named it explicitly, but it
  is a subclass instance, not a separate structure.
- **Schema:** as Subclass, plus `channelDivinityDesc`, domain `subclassSpells` by level.
- **Detail view:** identity(domain name) · stat block(domain spells, CD options, bonus profs) ·
  computed(CD uses at level, Destroy-Undead CR threshold) · rules text · cross-links(Cleric,
  Channel Divinity action, Turn Undead).
- **Count:** 14 (Life, Light, Trickery, Knowledge, Nature, Tempest, War, Death, Arcana, Forge,
  Grave, Order, Peace, Twilight).

### 5.4 Ability Scores, Skills & Saving Throws  ✅
- **Purpose:** the six scores; 18 skills; six saves. The left-column Abilities panel.
- **Schema:** AbilityScores{str…cha}; SKILLS[18] (key,label,ability,description);
  savingThrowProficiencies[]; skillProficiencies{skill→proficient|expert}.
- **Detail view (per skill / per save):** identity(name, governing ability) · stat block(prof
  state) · computed(total = mod + prof/expert + equipment + aura + condition delta, with the
  breakdown shown as labeled terms) · rules text(what the skill/save covers) · controls(toggle
  proficiency/expertise) · cross-links(equipment/feats/conditions contributing).
- **5e rules:** ability modifier, proficiency/expertise, Jack-of-All-Trades, passive Perception,
  Aura of Protection, condition save deltas.
- **Count:** 6 abilities · 18 skills · 6 saves.

### 5.5 Race (and subrace)  ✅
- **Purpose:** ancestry; ability bonuses, speed, darkvision, natural AC, traits, racial actions,
  racial spells, save advantages, bonus HP.
- **Schema (`RaceDef`, `raceData.ts`):** id, label, speed, abilityBonus, traits[], naturalAC?,
  size, bonusWeaponProficiencies?, bonusHpPerLevel?, freeAbilityPoints?, freeFeat?, racialSpells
  {charLevel→ids}, darkvisionRange, racialActions[].
- **Detail view:** identity(race, size, speed) · stat block(ability bonuses, darkvision, traits,
  natural AC) · computed(natural AC at this DEX; racial spells available at level) · rules text ·
  cross-links(racial actions, racial spells, granted weapon profs).
- **5e rules:** racial traits, ASIs, innate spellcasting cadence, natural armor.
- **Count:** 37 races/variants (canonical = `raceData.ts`).

### 5.6 Racial Action  ✅
- **Purpose:** an active racial feature usable in play (Breath Weapon, Fey Step, Stone's
  Endurance, Healing Hands, Shift, Shell Defense, Feline Agility…), with economy + recharge.
- **Schema (`RacialAction` in `racialActions.ts` / on RaceDef):** id, name, economy(action/
  bonus/reaction/free/passive), recharge(short/long/none), uses formula, effect/description.
- **Detail view:** identity(name, economy, recharge) · stat block(cost, uses) · computed(uses
  left this cycle, scaling damage/heal at level) · rules text · controls(spend a use / reset on
  rest) · cross-links(parent race).
- **Count:** ~15 races wired in 1.0; **[NEW IN 2.0]** finish the remaining ~25 (per project memory).

### 5.7 Feat  ✅ / 🟡
- **Purpose:** optional ability taken via ASI, race free-feat, or the dedicated Add-Feat flow;
  may grant ability bonus/choice, flags, or spells.
- **Schema (`FeatDef`, `featsData.ts`):** id, name, description, abilityBonus?, abilityChoice?[].
  Character carries feats[], featChoices{featId→ability}, and feat flags.
- **Detail view:** identity(name, source) · stat block(ability bonus/choice, flags it sets) ·
  computed(effect on AC/saves/attacks if any) · rules text · controls(add / remove / pick
  ability choice / pick granted spell) · cross-links(granted spells, related actions).
- **5e rules:** half-feat +1, prerequisite checks, granted-spell rules, crit riders (Piercer/
  Crusher), Spell Sniper range/cover, GWM/Sharpshooter.
- **Count:** 51 (37 PHB + 14 Tasha's). **[NEW IN 2.0]** enforce prerequisites; symmetric
  reversal of granted spells/abilities on removal (carry the `featChoices` lesson forward and
  extend it to granted spells).

### 5.8 Spell  ✅ / 🟡
- **Purpose:** a castable spell; the largest content set and the richest detail view.
- **Schema (`SpellEntry`, `spellData.ts`):** id, name, level(0–9), school, castingTime, range,
  components, duration, concentration, ritual, classes[], attackType(attack-roll|save|auto-hit),
  saveAbility, damageType, damageFormula, scalingDice, aoeShape/Size, attackBuff(toHit/bonusDmg),
  grantsTempHp/tempHpPerUpcast, setsBaseAC, multiTargetScaling, summons{templateId,count},
  vizCategory, vizAsset.
- **Detail view:** identity(name, level, school, ritual/concentration badges) · stat block(time,
  range, components, duration, save/attack, damage) · computed(THIS character's save DC, attack
  bonus, damage at chosen slot level incl. upcast + riders, temp HP granted) · rules text +
  higher-levels · controls(cast at slot level → spend slot, set concentration, register
  end-of-turn, toggle buff, summon) · **visualization slot** (below) · cross-links(conditions it
  imposes, summon templates, classes).
- **[IN SCOPE FOR 2.0 v1] Spell-effect visualization:** the detail view has a viz slot driven by
  `vizCategory` (self-buff / debuff-aura / terrain / heal / icon / wall / projectile) + `vizAsset`
  (sprite key). Build a small, data-driven **sprite/animation subsystem** mapping these keys to
  assets; spells without a viz fall back to the stat block. 1.0 has a partial sprite/GIF pipeline
  as reference (auras/terrain/summons/icons/walls wired; heal/vanish/counter not) — 2.0 completes
  and generalizes it.
- **5e rules:** slots/upcasting, concentration, ritual casting, attack vs. save resolution,
  AoE, components.
- **Count:** 199 (canonical = `spellData.ts`).

### 5.9 Item — Weapon  ✅
- **Purpose:** equippable weapon (main/off-hand), with damage, properties, enchantment, riders.
- **Schema (`Weapon` on character; `WeaponDef` + `weapons.csv`):** id, name, damage, damageType,
  rangeType, properties[], enchantmentBonus, bonus damage dice/flat, twoHanded, to-hit riders,
  crit modifier, requiresAttunement, isMonkWeapon, cost, rarity, sprite.
- **Detail view:** identity(name, rarity, sprite) · stat block(damage dice, type, properties,
  enchant) · computed(to-hit and damage FOR this character incl. ability mod, profs, riders;
  crit threshold) · rules text(properties explained) · controls(equip main/off-hand, attune,
  sell) · cross-links(fighting styles, feats, special attacks it enables).
- **Count:** ~57 (`public/equipment_data/weapons.csv`, CSV columns are the schema).

### 5.10 Item — Gear (armor / shield / accessory)  ✅
- **Purpose:** body armor, shields, and 10 accessory slots (helmet/necklace/cape/legs/boots/
  gloves/quiver/2 rings/amulet) granting AC, ability/save/skill bonuses, advantage, damage riders.
- **Schema (`GearEquipmentItem` + `gear.csv`):** id, name, kind(slot), type(armor class), baseAC,
  dexCap, stealthDisadvantage, strRequirement, enchantmentBonus, requiresAttunement, stats{ac/
  toHit/speed/ability/save/skill bonuses, advantage, bonusDamage}, cost, rarity, sprite.
- **Detail view:** identity(name, slot, rarity) · stat block(AC/cap/stealth/str-req, stat bonuses,
  advantages) · computed(net effect on this character's AC/saves/skills) · rules text · controls
  (equip to slot, attune, sell) · cross-links(slot, set/aura interactions).
- **Count:** ~80 (`public/equipment_data/gear.csv`).

### 5.11 Item — Custom/Homebrew  ✅
- **Purpose:** user-created gear/weapons with arbitrary stat bonuses.
- **Schema:** same as Gear/Weapon; persisted under a custom-items store, editable.
- **Detail view:** identity + stat block + computed + **edit form** (the controls slot becomes a
  full editor: name, rarity, cost, bonuses) + cross-links.
- **Count:** unbounded (user data).

### 5.12 Condition  ✅
- **Purpose:** status states (the 14 PHB conditions + terrain/spell states); fold into AC/speed/
  saves where computable, else flag the manual rule.
- **Schema (`Condition`, `conditionsData.ts`):** id, name, category(debuff|buff|neutral),
  description, effects[]{affects, description, mechanic:{speedMultiplier|acDelta|flatSaveDelta|
  flag}}.
- **Detail view:** identity(name, category color) · stat block(each effect + its mechanic) ·
  computed(this character's resulting AC/speed/save deltas) · rules text · controls(apply/remove)
  · cross-links(spell/feature that causes it). **[NEW IN 2.0]** respect condition immunities.
- **Count:** 21 (16 PHB-core + difficult-terrain, silence, slowed, fly, haste) — canonical
  `conditionsData.ts`.

### 5.13 Buff & Debuff  ✅
- **Purpose:** the user named these explicitly. In the model: **buffs** are mostly active spell
  effects (Mage Armor sets base AC; Bless/Hunter's Mark/Divine Favor add attack riders;
  False Life/Heroism grant temp HP) carried in `activeBuffSpells[]`; **debuffs** are conditions
  with negative mechanics (category `debuff`). Buff = positive category condition OR active buff
  spell; debuff = negative condition.
- **Schema:** buffs → `activeBuffSpells[]` (spell ids) + spell `setsBaseAC`/`attackBuff`/
  `grantsTempHp`; debuffs → conditions with debuff category.
- **Detail view:** as Spell (for buff spells) or as Condition (for status buffs/debuffs), with
  the computed slot showing the live AC/attack/temp-HP/save effect, and a toggle control.
- **5e rules:** concentration on buff spells, stacking rules, AC-set vs. AC-add.
- **Count:** buff spells ~dozen wired; debuff conditions = the debuff-category subset of §5.12.

### 5.14 Action / Bonus Action / Reaction  ✅
- **Purpose:** the center-column action list — everything the character can do on a turn,
  grouped by economy type, with resource costs and depletion.
- **Schema (`ActionDef` from `getAvailableActions`):** name, type(Action|Bonus Action|Reaction|
  Free), short, full, resourceKey?, resourceCost?, requiresLevel?, classOnly?.
- **Detail view (ActionDetailPanel):** identity(name, economy badge) · stat block(cost,
  requirements) · computed(for attack/spell actions: live to-hit/damage/DC; uses remaining) ·
  rules text · controls(perform → spend economy/resource; cast; attack; fire rider) ·
  cross-links(weapon/spell/feature/resource backing it).
- **5e rules:** the action economy (1 action + 1 bonus + 1 reaction/round), Extra Attack,
  Action Surge granting extra actions, readied reactions, opportunity attacks, casting-time rules.
- **Count:** ~14 generic + dozens of class/subclass/feat/weapon-derived (computed, not a fixed
  list). **[NEW IN 2.0]** legendary/lair actions for summons.

### 5.15 Turn Economy & Next-Turn Checklist  ✅
- **Purpose:** track per-turn used/available action/bonus/reaction pips (incl. granted extras),
  and an end-of-turn checklist (drop concentration/conditions/buffs/rage/Bladesong, list expiring
  spells).
- **Schema (`TurnState`):** actionsUsed/bonusActionsUsed/reactionsUsed, bonus* grants,
  endOfTurn(Spell|Buff)Ids[], divineStrikeFired.
- **Detail view:** the TurnHeader (pips) + NextTurnChecklist (confirmable end-of-turn decisions).
- **5e rules:** action economy reset each turn; 1-round/end-of-turn durations; concentration.

### 5.16 Resource  ✅
- **Purpose:** class/subclass pools — Ki, Rage, Sorcery Points, Bardic Inspiration, Channel
  Divinity, Action Surge, Second Wind, Lay on Hands, Superiority Dice, Infusions, Mystic Arcanum,
  War Priest, Fighting Spirit, etc.
- **Schema:** `resources{name→{used,total}}`; defaults from `getResourceDefaults(class,level,
  scores)`; recharge tied to rest type.
- **Detail view:** identity(resource name) · stat block(used/total, recharge cycle) · computed
  (total at this level/ability) · rules text · controls(spend/restore; reset on rest) ·
  cross-links(actions that spend it, rest that restores it).
- **Count:** dozens across classes/subclasses (canonical = `resourceDefaults.ts` + ClassDef.resources).

### 5.17 Rest — Short & Long  ✅
- **Purpose:** the rest dialog. Short: spend Hit Dice (roll + CON), recover short-rest resources,
  Warlock slots, racial recharges. Long: full heal, recover HD (½ level), reset all resources/
  slots/prepared, drop concentration/summons/rage/Bladesong, clear conditions except exhaustion.
- **Schema:** drives `shortRest(id, hdRolled)` and `longRest(id)` state actions.
- **Detail view:** the Rest overlay — short/long tabs; HD selector with roll preview; a summary
  of what each rest restores; confirm.
- **5e rules:** Hit Dice economy, rest-based recharge, exhaustion recovery (−1 per long rest).

### 5.18 Inventory  ✅
- **Purpose:** owned but not-equipped items; a grid with drag-drop to equipment slots; gold;
  attunement (max 3).
- **Schema:** `ownedItemIds[]`, `attunedItemIds[]`, `gold`; item defs from gear/weapon registries
  + custom store.
- **Detail view:** per-item = the Item detail view (§5.9–5.11) with equip/attune/sell controls;
  the grid itself shows owned items with slot affordances.
- **5e rules:** attunement limit (3), attunement conflicts, equip/slot rules.

### 5.19 Shop  ✅
- **Purpose:** browse and buy equipment with gold; weapons + armor + accessories from the catalog.
- **Schema:** aggregated `SHOP_ITEMS` (gear+weapons); `buyItem`/`sellItem` adjust gold + inventory.
- **Detail view:** per-item = Item detail view with a **buy** control + price; filters by slot/
  rarity/cost.
- **5e rules:** item costs/rarity (economy is app-defined; no strict 5e pricing rule).

### 5.20 Summon  ✅
- **Purpose:** conjured/animated creatures & structures with their own statblock, HP, conditions,
  and action economy; template→base→runtime split (template editable; base locked at summon time;
  runtime mutable).
- **Schema (`entities/summon/types.ts`):** SummonTemplate(name,type,maxHp(+formula),ac,speed,
  initiativeMod,attacks[],actionEconomy,spells?,resources?,abilityScores?,saveProfs?,PB,
  usesCasterPB) → SummonBase(locked snapshot) → ActiveSummon(hp,conditionIds,economyUsed,
  resourcesUsed,initiativeRoll,notes,concentration).
- **Detail view (SummonDetailPanel):** identity(label, type) · stat block(HP/AC/speed/attacks/
  abilities) · computed(PB if usesCasterPB; attack lines) · rules text(notes) · controls(edit HP/
  temp-HP, apply conditions, spend economy, new-turn reset, remove) · cross-links(source spell/
  feature, template). Catalog/editor overlay = create/edit templates.
- **5e rules:** summon statblocks, concentration linkage (summons drop when caster drops
  concentration), per-summon turn economy. **[NEW IN 2.0]** legendary/lair actions; condition
  immunities on summons.
- **Count:** 20+ built-in templates + unbounded custom (`summonTemplates.ts` / summon JSON).

### 5.21 Class/Subclass/Race Feature  ✅
- **Purpose:** the descriptive + mechanical features listed by source in the Features panel
  (Second Wind, Sneak Attack, Wild Shape, Rage, Channel Divinity, Aura of Protection, fighting
  styles, racial traits, custom notes).
- **Schema (`FeatureEntry`):** level, name, desc; assembled by `getClassFeatures(class,level)` +
  subclass features + race traits + fighting style + custom.
- **Detail view (FeatureDetailPanel):** identity(name, source badge, level) · stat block(any
  numeric: uses, dice) · computed(scaling at level) · rules text · controls(pick subclass/
  fighting style when the feature is a choice; edit/remove custom) · cross-links(resource/action
  the feature grants).
- **Count:** ~60+ leveled features across 12 classes + 112 subclasses + race traits.

### 5.22 Sub-systems carried as feature data (catalog as their own detail views)  ✅/🟡
The user said "everything" — these specialized pools each get a detail view via §2:
- **Fighting Styles** (`fightingStylesData.ts`) — choice feature; AC/attack/damage riders.
- **Warlock Invocations** (`invocationsData.ts`, 20) — pick N by level; passive/active effects.
- **Artificer Infusions** (`infusionsData.ts`, 17) — known/active caps by level; item grants.
- **Battle Master Maneuvers** (`maneuversData.ts`, 17) — known by level; superiority dice.
- **Arcane Shots** (`arcaneShotsData.ts`) — Arcane Archer options; INT DC.
- **Rune Knight Runes** (`runeData.ts`, 7); **Psi Warrior** disciplines; **Wild Magic surge**
  table (`wildSurgeTable.ts`).
- Each: identity → stat block(known/active/uses) → computed(caps at level) → rules text →
  controls(choose/toggle/spend) → cross-links(parent subclass, resource).

### 5.23 Background  ✅
- **Purpose:** origin granting skill/tool proficiencies, a feature, sometimes a feat.
- **Schema (`BackgroundDef`):** id, label, skills[2], tools?[], feature, feat?.
- **Detail view:** identity(label) · stat block(granted skills/tools) · rules text(feature) ·
  cross-links(granted feat, skills).
- **Count:** 13.

### 5.24 Character lifecycle (create / select / level-up)  ✅
- **Character-Select** overlay: list, create (class/race/ability method: point-buy / roll /
  standard array), delete.
- **Level-Up** flow: HP gain, proficiency bump, subclass pick at the class's level, ASI-vs-feat
  choice, spell/cantrip selection deltas, resource/slot recompute. **[NEW IN 2.0]** multiclass
  level-up (choose which class to advance; prerequisite check).
- **Detail view:** the Level-Up modal as a guided multi-step flow; Spell-Selection step is its
  own constrained picker (filters, known/prepared deltas).

## 6. Build sequencing for the AI agent (recommended order)

Stack-agnostic, so the agent can pick a stack, but build in dependency order:
1. **Rules engine (§3)** as pure functions + **data schemas (§4/§5)** — no UI. Unit-test each
   rule against 5e-correct numbers. This is the foundation everything derives from.
2. **Data registries — re-derived clean** (1.0 files are reference only). Rebuild the 12 classes /
   112 subclasses / 37 races / 51 feats / 199 spells / equipment / summon templates with
   consistently re-keyed ids and 1.0 inconsistencies fixed, preserving the same coverage counts.
   Validate counts + id resolution against 1.0 as a checklist, not by copying.
3. **Persistence adapter (§4)** + the **v11 importer**.
4. **State layer** — character aggregate + actions (update, addFeat, levelUp, rests, equip,
   summon, turn economy) calling the rules engine.
5. **Shell (§1)** — header + 3 columns + responsive drawer.
6. **Universal detail-view component (§2)** — ONE polymorphic panel.
7. **Entity panels (§5)** — left/center columns wired to selectors + the detail view.
8. **[NEW IN 2.0] surfaces** — **full-PHB multiclassing**, condition immunities/resistances,
   legendary/lair actions, remaining racial actions, and the **spell-visualization subsystem**
   (in scope for v1 — fold into the spell detail view as it is built, not as a trailing pass).

## 7. Verification

- **Rules engine:** unit tests per §3 function with 5e-correct expected values (AC formulas at
  representative builds; spell DC/attack; upcast damage; multiclass slot table; rest recovery;
  condition folding). Mirrors 1.0's test suites (charCalculations / rules / migrations / equipment

- **Data integrity:** counts match (12/112/37/51/199/…); every `*_BY_ID` derives from its array;
  every referenced spell/feat/condition/summon id resolves.
- **Persistence round-trip:** save→load a character on both adapters yields an identical document;
  a real v11 fixture imports without loss into the 2.0 schema.
- **Detail-view contract:** for each entity type in §5, opening its detail view renders the six
  slots correctly and its controls dispatch the right state change (spot-check one per type).
- **End-to-end:** create a character → level up (incl. one multiclass step) → equip/buy gear →
  prepare/cast a spell with concentration → apply a condition and see AC/speed/save change →
  summon a creature → short and long rest restore correctly.
