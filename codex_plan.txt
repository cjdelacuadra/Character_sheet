---- V2 COMMAND PATTERN (UNDO) ----

File: src/renderer/src/app/store/commands.ts (new file)

Interface CharacterCommand:
  type: string
  characterId: string
  apply: (state: Character) => Character
  undo: (state: Character) => Character
  description: string   e.g. "Dealt 12 damage"

uiSlice maintains a stack of the last 10 commands per character.
Ctrl+Z calls undo() on the top command and pops the stack.
Every character mutation goes through applyCommand().
applyCommand() validates the next state with CharacterSchema.safeParse()
before applying; if invalid, shows an error toast and returns without mutating.

---- V2 SPELLBOOK PANEL (Was Missing) ----

File: src/renderer/src/features/spells/SpellbookView.tsx (new file)
File: src/renderer/src/features/spells/PreparedSpellsList.tsx (new file)

Access: "Spellbook" tab in center column (alongside Actions tab group)

Two sub-views by class type:

  Known Spells (Bard, Ranger, Sorcerer, Warlock):
    List of currently known spells with option to swap on level-up

  Prepared Spells (Cleric, Druid, Paladin, Wizard):
    Total available spells, current prepared count vs max, toggle to mark prepared

Prepared max formulas:
  Cleric/Druid: WIS modifier + character level
  Paladin: CHA modifier + floor(paladin level / 2)
  Wizard: INT modifier + character level

Both sub-views support:
  Search and filter by level, school, concentration
  Click any spell: opens spell card modal
  "Add Spell" button: filtered spell selection (restricted by class + level)

Prepared state resets on long rest (user re-marks).

Edge cases:
  Wizard with 0 prepared spells: show warning "No spells prepared"
  Adding spell above current slot level: blocked with explanation

---- V2 COMPONENT WRITING RULES ----

1. Max 300 lines per component; extract sub-components if exceeded.
2. No derived stat computation in JSX; use useDerivedStats() exclusively.
3. No direct store mutations in event handlers; dispatch a command through
   store.applyCommand().
4. No magic strings; use typed enums/constants for all IDs.
5. Every component wrapped in PanelErrorBoundary except primitive shared/ui
   components.
6. No CSS values hardcoded in components; always reference design tokens via
   var(--color-*), var(--space-*).


---- V2 DOMAIN LAYER RULES ----

1. All functions in domain/rules/ are pure; zero React, zero Zustand imports.
2. Every function has a corresponding Vitest test file (*.test.ts).
3. Test edge cases: max ability score (30), level 20, 0 HP, no proficiency,
   magic weapons, shield stacking.
4. No domain function reads from static data files; data is passed as parameters.


---- V2 STATE MANAGEMENT RULES ----

1. characterSlice.ts: Only character data mutations + IPC persistence calls.
2. uiSlice.ts: Only UI state (open panels, active tabs, undo stack, toasts).
3. Selectors colocated with features (features/vitals/useVitals.ts).
4. No useAppStore() calls in leaf components; they receive props from feature
   root components.


---- V2 IPC LAYER RULES ----

1. All IPC calls go through services/ipc.ts (DONE).
2. Every IPC call is async/await with try/catch; errors show a toast.
3. Save is debounced 500ms; prevents excessive writes on rapid HP clicks.


---- V2 CSS RULES ----

1. All color/spacing/typography from tokens.css; zero hardcoded values.
2. Module CSS for component-scoped styles.
3. Shared layout primitives in shared/ui/.
4. Media queries for tablet layout at max-width: 999px (DONE in CharacterView).
